# 機能仕様

## 画面一覧

| 画面 | パス案 | 説明 |
| --- | --- | --- |
| 本一覧 | `/books` | 登録済みの本を一覧表示し、検索と絞り込みを行う |
| 本登録 | `/books/new` | 新しい本を登録する |
| 本詳細 | `/books/:id` | 1冊の詳細情報を表示する |
| 本編集 | `/books/:id/edit` | 登録済みの本を編集する |
| 保管場所管理 | `/locations` | 保管場所タグを登録、編集、無効化する |
| 分類タグ管理 | `/classification-tags` | 分類タグを登録、編集、無効化する |
| データ入出力 | `/data` | 蔵書データのExport/Importを行う |

MVPではトップページ `/` は `/books` に誘導します。

## 共通ナビゲーション

- PCではサイドバーに全画面へのナビゲーションを表示する
- 画面幅が狭い場合は、横スクロールを使わず、メニューボタンから全項目を縦並びで表示する
- メニューはマウス、タッチ、キーボードで開閉でき、現在の画面を選択状態として示す
- スマホのメニューは本文を押し下げず、その上に重ねて表示する
- メニュー項目の選択、メニュー外のタップ・クリック、Escapeキーでメニューを閉じる。メニュー外のタップは背後の操作を実行せず閉じる操作だけを行う。項目選択後の画面遷移とキーボードフォーカスを維持する
- スマホのリンク・ボタンなどでブラウザ固有の青いタップハイライトを抑え、キーボードのフォーカス表示は維持する
- SPA内のリンクによるページ遷移はスクロール位置を先頭に戻し、途中から詳細ページが表示されないようにする

## 共通APIステータス

- APIヘルスチェック中およびAPIとデータベースが正常な場合は、常時表示の接続バッジを表示しない
- 初回ヘルスチェックでAPIまたはデータベースに問題がある場合だけ、ヘッダーに警告を表示する
- 警告の詳細には、Backendのサービス名、エラー内容、データベース状態、接続先を表示する

- 出版日（カード上で表示し、未設定の場合も明示）
- ISBN
- 本のバーコード
- 管理用バーコード
- 保管場所
- 分類タグ
- 更新日時

### 操作

- キーワード検索
- 保管場所タグによる絞り込み
- 分類タグによる絞り込み
- 並び順と昇順、降順の切り替え
- 詳細画面への遷移
- 登録画面への遷移
- 削除

### 表示モード

- カード表示では保管場所ラベルの下にタイトルと著者を配置し、強調する左側の縦線はタイトルと著者のみに付ける。ISBN・本のバーコード・管理用バーコードは「詳細情報」を展開したときだけ表示する。更新日時は並び順の確認に使えるよう小さく控えめに表示する
- PCでは、カード表示と情報量を抑えた密度高めの一覧表示を切り替えられる
- 密度高めの一覧では、タイトル、著者、出版日、保管場所、識別情報、分類・更新日時、操作を同じ行にまとめる
- スマートフォンではカード表示を使い、密度高めの一覧を選択していてもカード表示へ切り替える
- 現在の並び順と昇順、降順は一覧上部に表示する

### 検索対象

- タイトル
- 著者
- ISBN
- 本のバーコード
- 管理用バーコード

### 並び替え

- 登録日時、更新日時、タイトル、著者、出版社、出版日を選択できます。
- 昇順、降順を切り替えできます。
- 検索、絞り込み、ページ移動を行っても選択した並び順を維持します。

## 本登録

### 入力項目

| 項目 | 必須 | 説明 |
| --- | --- | --- |
| タイトル | 必須 | 本の名前 |
| 著者 | 任意 | 複数名はカンマ区切りで入力 |
| 出版社 | 任意 | 出版社名 |
| 出版日 | 任意 | `YYYY`、`YYYY-MM`、`YYYY-MM-DD` 形式。NDL由来の `YYYY.M` は保存時に `YYYY-MM` へ正規化 |
| 本のバーコード / ISBN | 任意 | 有効なISBN-10はISBNとして、有効なISBN-13は本のバーコードとISBNとして保存。ISBNではない値は本のバーコードとして保存 |
| 管理用バーコード | 任意 | 利用者が独自に貼付する管理用バーコード |
| 保管場所 | 任意 | 事前登録した保管場所タグから選択。本登録・編集画面から新規追加もできる |
| 分類タグ | 任意 | 外部APIのsubject/genre由来候補、事前登録した分類タグ、または本登録・編集画面で追加したタグから選択 |
| 管理メモ | 任意 | 破損、付属品、棚卸し補足などの管理用メモ |

入力欄の補足説明（バーコード / ISBN、管理用バーコード、著者、出版日、保管場所、管理メモなど）はラベル横の丸い「？」から開きます。タップ・クリックで開閉でき、外側のタップや Escape キーでも閉じられます。入力エラーや重複警告は入力欄の近くに常時表示します。

### バーコードによる書誌情報取得

本登録、編集画面は次の順序で操作できるようにします。

1. 本のバーコード / ISBNを入力する
2. 必要に応じてカメラで読み取り、読み取り結果の入力先を選ぶ
3. 外部APIで照会し、取得した書誌情報を確認・補正する
4. 保管場所、分類タグ、管理メモを設定して保存する。必要な保管場所や分類タグがない場合は、フォームを離れずに追加してそのまま選択する

カメラ読み取り、外部API照会、手入力の書誌情報欄は同じ登録フロー内で連続して確認できるようにします。保存、キャンセル操作は長いフォームの末尾で確認でき、モバイルでも画面から離れすぎないようにします。

- 入力値がISBNまたはISBNとして解釈できる本のバーコードの場合、明示的な照会操作で外部APIから書誌情報を取得します。
- 外部APIはNDLサーチAPIを優先し、見つからない場合のみOpen Library APIへフォールバックします。
- 本のバーコード / ISBNがISBNとして解釈できる場合は、NDLサーチOpenSearch APIで完全一致照会します。
- 本のバーコードがISBNとして解釈できない場合は、読み取り値として保存し、書誌情報は手入力します。
- NDLサーチで取得できない場合は、Open Library ISBN APIで完全一致照会します。
- 完全一致で取得できた場合は、その書誌情報をフォームに自動入力します。
- NDLサーチ、Open Libraryのどちらでも取得できない場合は、候補検索へフォールバックせず手入力登録に進みます。
- 同じISBNの照会結果はSQLiteにキャッシュし、取得できなかった結果も短期間キャッシュします。
- MVPでは外部APIによる候補選択UIは実装しません。
- 取得対象はタイトル、著者、出版社、出版日、ISBN、subject、genreを基本とします。
- 外部APIに巻情報がある場合は、巻または巻タイトルをタイトル末尾へ補足し、登録前にユーザーが編集できるタイトルとして表示します。既に同じ情報を含む場合は重複させません。
- 取得できた項目は登録フォームに自動入力します。
- NDLサーチのsubjectは、`xsi:type` や `rdf:datatype` などの型指定がない主題語を分類タグ候補として表示します。
- NDLサーチの`dcndl:genre`は、ジャンル・形式用語として分類タグ候補に含めます。
- NDLサーチの`dcndl:NDC9`またはNDC9分類URIのsubjectは、日本図書館協会のNDC9 Linked Dataを照合し、文脈付き分類項目名を分類タグ候補として表示します。
- NDC8、NDC10、版不明のNDC、NDLCなどの未対応分類記号と、NDC9マスタに存在しない分類記号は表示しません。未解決のコードをそのままタグ名として表示することもありません。
- 分類タグ候補は自動保存せず、ユーザーが選択したものだけ外部API由来タグとして保存して本に紐づけます。
- 本登録・編集画面から手動追加した分類タグは `source: "manual"` として保存し、作成成功後に現在のフォームへ自動選択します。
- 手動追加時に同名の有効な分類タグがある場合は新規作成せず既存タグを選択し、無効な分類タグがある場合は分類タグ管理画面での再有効化を案内します。
- 取得できなかった場合も、手入力で登録できます。
- 外部APIは入力補助であり、外部APIが利用できない状態でも手入力で本を登録できます。
- 管理用バーコードは書誌情報取得には使わず、蔵書の一意識別に使います。
- ISBN、読み取りバーコード、管理用バーコードの違いは、主入力欄と個別編集の詳細欄付近で説明します。
- 本のバーコード / ISBNは入力後に短い待ち時間を置いて既存データと完全一致確認し、登録済みの本がある場合は入力欄直下へ小さな赤字警告と詳細リンクを表示します。
- ISBN-10と978 ISBN-13は同一のISBNとして確認し、979 ISBN-13はISBN-10へ変換せず確認します。ISBNではないバーコードは値そのものだけで確認します。
- 編集時は編集中の本自身を重複警告の対象から除外し、本のバーコード / ISBNの重複は警告だけで保存を妨げません。
- 管理用バーコードは同じ完全一致確認を行いますが、保存時の一意制約と409エラーは維持します。
- MVPのバーコード入力は、バーコードリーダーがキーボード入力として値を送る方式を前提にします。
- カメラによるバーコード読み取りは優先事項として扱います。

### ISBN、JAN、バーコードのヘルプ

本登録、編集画面では、本のバーコード / ISBN入力欄の近くに、値の解釈と保存先を説明するヘルプを配置します。

ヘルプでは以下を説明します。

- 本のバーコードには複数種類があります。
- 日本の書籍の2段バーコードでは、上段がISBN由来の書籍JANコード、下段が価格などを含むコードであることが多いです。
- 書誌情報を取得したい場合は、主入力欄へISBNまたはISBNとして解釈できる上段バーコードを入力・読み取ります。
- 雑誌や古い本など、ISBNではないバーコードもあります。その場合は本のバーコードとして保存し、書誌情報は手入力します。
- ISBN-10は物理バーコードとして扱わずISBNだけに保存し、ISBN-13は本のバーコードとISBNの両方に保存します。
- 既存データなどでISBNと本のバーコードが異なる場合は、個別編集の詳細欄から両方を確認・編集できます。
- 管理用バーコードは利用者が独自に貼る蔵書管理用IDであり、書誌情報取得には使いません。

ISBNではない値を読み取った場合は、本のバーコード / ISBN欄に値を反映し、「ISBNではない可能性があります。必要に応じて書誌情報を手入力してください。」という案内を表示します。

### カメラ読み取り連携

- 初期フロントエンドはWebアプリケーションとして提供します。
- HTTPSなどブラウザのカメラ利用条件を満たす環境では、Web画面内でのカメラ読み取りを優先します。
- HTTP環境ではブラウザのカメラ利用に制約があるため、Web画面内のカメラ読み取りだけに依存しません。
- 登録フォームにはコンパクトなカメラ起動ボタンだけを表示し、要求時にビューポート内へ収まるモーダルを開きます。モーダル表示中は背景のスクロールを抑止します。
- Web画面のカメラ読み取りは、ブラウザ標準の `getUserMedia` と `@zxing/browser` を利用します。キャンセル、Escape、読み取り成功、アンマウント、カメラエラーのいずれでもカメラストリームを停止します。
- 読み取り結果は本のバーコード / ISBNまたは管理用バーコードのどちらへ入力するかをユーザーが選択できます。本のバーコード / ISBNへ入力した値は手入力と同じ規則で解釈します。
- カメラ読み取り成功時は、手入力のデバウンスを待たずに同じ完全一致確認を開始します。確認に失敗した場合は一意であるとは表示せず、入力と保存操作は維持します。
- カメラ読み取りに対応しないブラウザや権限がない環境では、手入力またはキーボード入力型バーコードリーダーを使えるよう案内します。
- MVPでは、読み取り結果を本のバーコードまたは管理用バーコードの文字列として受け取れるAPI設計を優先します。
- 将来的にAndroidフロントエンドを追加する場合も、Webフロントエンド専用の内部状態に依存せず、同じバックエンドAPIへ接続できるようにします。
- バーコード読み取り、書誌情報取得、本登録は分離し、フロントエンド実装がWebでもAndroidでも既存の本登録APIを使い回せるようにします。
- AndroidフロントエンドはMVP対象外ですが、HTTP環境でカメラ利用が必要になった場合の有力な選択肢として想定します。

### バリデーション

- タイトルは1文字以上、200文字以下
- ISBNは未入力、有効なISBN-10、ISBN-13のいずれかを許可し、保存時は数字と `X` のみに正規化
- 本のバーコードは未入力、または任意の読み取り値を許可
- 管理用バーコードは未入力を許可するが、入力された場合は一意である必要があります
- 出版日は未入力、または有効な年、年月、年月日のみ許可
- 保管場所は有効な保管場所タグのみ新規に紐づけできます。既存の本に紐づいた保管場所タグが後から無効化された場合、その本の編集時に同じ保管場所を維持することは許可します。
- 分類タグは有効な分類タグのみ新規に紐づけできます。既存の本に紐づいた分類タグが後から無効化された場合、その本の編集時に同じ分類タグを維持することは許可します。
- 管理メモは5000文字以下

### 入力エラーからの復旧

- APIから返されたフィールド単位のエラーは、該当する入力欄の近くに表示する
- エラーがある場合は先頭の入力欄へフォーカスし、修正対象を画面上部のエラー一覧から確認できる
- JSON Importの構造エラーはJSON入力欄を修正対象として案内し、修正後に再度プレビューできる

- 将来的に削除履歴が必要になった場合は論理削除へ変更します。

## 保管場所管理

### 表示項目

- 保管場所名
- 説明
- 表示順
- 有効、無効

### 操作

- 保管場所タグを登録する
- 保管場所タグを編集する
- 使わなくなった保管場所タグを無効化する
- 無効化した保管場所タグを再有効化する
- 本登録・編集画面から保管場所名と説明を入力して保管場所タグを追加する

### 振る舞い

- 本の登録、編集では有効な保管場所タグのみ選択できます。
- 本登録・編集画面で追加した保管場所タグは、作成成功後に現在のフォームへ自動選択されます。
- 保管場所タグの追加保存は本の登録、編集とは独立しているため、本の登録をキャンセルしても追加した保管場所タグは残ります。
- 保管場所タグの追加に失敗した場合は、書籍フォームの入力内容を保持したまま、入力エラーまたはAPIエラーを追加パネル内に表示します。
- 既に本に紐づいている保管場所タグは削除せず、無効化します。
- 誤って無効化した場合や再利用する場合は、有効状態へ戻せます。
- MVPでは1冊の本に設定できる保管場所タグは1つとします。

## 分類タグ管理

### 表示項目

- 分類タグ名
- 説明
- 有効、無効

### 操作

- 分類タグを登録する
- 分類タグを編集する
- 使わなくなった分類タグを無効化する
- 無効化した分類タグを再有効化する
- 本登録・編集画面から分類タグ名と説明を入力して分類タグを追加する

### 振る舞い

- NDLサーチから取得した主題語subjectとgenre、またはOpen Library APIから取得したsubjectsは分類タグ候補として表示します。
- ユーザーが確定した候補のみ分類タグとして保存します。
- 本登録・編集画面で追加した分類タグは、作成成功後に現在のフォームへ自動選択されます。
- 手動追加時の名前重複は大文字小文字を区別せずに確認し、有効な既存タグは選択、無効な既存タグは再有効化を案内します。
- 分類タグの追加保存は本の登録、編集とは独立しているため、本の登録をキャンセルしても追加した分類タグは残ります。
- 本の登録、編集では複数の分類タグを紐づけできます。
- 既に本に紐づいている分類タグは削除せず、無効化します。
- 誤って無効化した場合や再利用する場合は、有効状態へ戻せます。

## データ入出力

### Export

- 本、保管場所タグ、分類タグをまとめてJSON形式でExportします。
- JSON Exportは、同じアプリのImportで復元できる正式なバックアップ、移行形式とします。
- 他ツールでの閲覧、分析向けにはCSV Exportを別機能として追加できるようにします。
- CSV Exportは復元用の正規形式ではなく、Excel、LibreOffice、Python、Rなどで確認、分析するための読み取り用形式として扱います。
- CSV ImportはMVPでは必須にせず、必要になった時点で列仕様と重複解決ルールを別途決めます。

### Import

- ExportしたJSONファイルをImportできます。
- Import前にバリデーション結果を表示します。
- Import前に追加、上書き候補、無視候補、エラーをプレビュー表示します。
- ExportとImportは画面上で明確に分け、Importがデータを変更する操作であることを表示します。
- 既存データと重複する場合は、Windowsでフォルダをコピーしたときのように、個別に上書きするか無視するかを選択できます。
- 重複項目に対して `すべて上書き` と `すべて無視` を選択できます。
- `すべて上書き` と最終Importの実行時は、対象件数と既存データを置き換える旨を確認します。
- 重複項目の初期選択は `無視` とし、意図しない上書きを避けます。
- 長い競合一覧でも、入力元とプレビュー概要、最終Import操作を確認し続けられるようにします。
- 保管場所タグ名、分類タグ名、管理用バーコードなどの重複は、Import重複解決ルールに従います。
- Import成功後はプレビューを閉じ、Import結果を表示します。再度同じJSONをImportする場合も、再プレビューを必要とします。
- ImportするJSON内でUUID、管理用バーコード、保管場所タグ名、分類タグ名、タグ紐づけペアが重複している場合は、既存データとの競合ではなくImport前エラーとして扱います。
- MVPでは既存データを全削除する置換Importは行わず、追加Importと選択的な上書きを基本とします。

## バックアップ

- セルフホスト環境では、SQLiteデータベースファイル `/data/book-manager.sqlite` をDocker volumeまたはホストディレクトリへマウントします。
- 通常のバックアップは、マウントされたSQLiteデータベースファイルをバックアップする運用を基本とします。
- Export/Importは、アプリケーション上でのデータ移行や部分的な取り込みに使います。
