# MVPスモークテスト

MVPのリリース前に、ローカル開発環境とDocker Composeのセルフホスト環境で最低限確認する項目です。各項目は上から順番に実施し、失敗した場合は原因と環境を記録します。

## 事前準備

- [ ] リポジトリの作業ツリーが意図したコミットになっている
- [ ] Node.js 24 LTS、pnpm 10、mise、Docker Composeが利用できる
- [ ] `.env.example` をコピーして `.env` を作成する

```powershell
Copy-Item .env.example .env
```

## ローカル起動

- [ ] `mise install` が成功する
- [ ] `mise run install` が成功する
- [ ] `mise run dev` でFrontendとBackendが起動する
- [ ] ブラウザで `http://localhost:3000` を開ける
- [ ] `http://localhost:3001/api/health` が次のJSONを返す

```json
{
  "ok": true,
  "service": "book-manager-backend",
  "database": "ok"
}
```

- [ ] APIとDBが正常な場合、Frontend上部に常時表示のAPI接続バッジが表示されない
- [ ] APIまたはDBのヘルスチェックに失敗した場合、Frontend上部の警告を開いてBackend APIの接続先、エラー内容、DB状態を確認できる
- [ ] 320〜430pxの画面幅でAPIが正常な場合、「メニューを開く」直下に空のヘッダー余白がなく、メニューを開閉できる
- [ ] スマホ（320/360/390/430px）のメニューを開いても本文が下へずれず、本文に重なるメニューが表示される。下の本文のタップ、外側クリック、項目選択、Escapeキーで閉じられる。メニュー外を閉じるタップが、背後のリンク・削除ボタン等を同時実行しない
- [ ] スマホでナビゲーションを選択すると画面遷移し、現在位置の表示とキーボードフォーカスの動きも維持される
- [ ] iOS Safari・Android Chromeなどでメニュー・リンク・ボタンのタップ時にブラウザ固有の青いハイライトが表示されず、キーボードのTab移動時にはフォーカスが視認できる
- [ ] フォーム・カード・モーダル・チップの角丸が要素ごとの統一された段階になっており、不自然なばらつきがない
- [ ] 320〜430pxの画面幅でもAPI警告が表示された場合は、警告を開いて診断情報を確認できる
- [ ] 終了時にFrontendとBackendのプロセスを停止する

通常のホスト側テストは、依存関係をインストールした後に `mise run typecheck`、`mise run test`、`mise run build` を実行します。

## Docker Compose起動

- [ ] `docker compose up --build -d` が成功する
- [ ] `docker compose ps` で `backend` と `frontend` が起動状態になる
- [ ] `http://localhost:3000` を開ける
- [ ] `http://localhost:3000/api/health` が `200 OK` と `database: "ok"` を返す
- [ ] Frontendから本一覧、保管場所、分類タグ、JSON Export/Importへ移動できる
- [ ] `docker compose logs backend` と `docker compose logs frontend` に起動エラーがない
- [ ] 確認後に `docker compose down` で停止する

Docker Composeでは、ホスト側の `node_modules` をコンテナへマウントしません。依存関係は各イメージ内に閉じ込め、ホスト側にはSQLiteの `./data:/data` だけをマウントします。

## MVP機能

- [ ] 保管場所を登録、編集、無効化できる
- [ ] 分類タグを登録、編集、無効化できる
- [ ] 本を必須項目だけで手入力登録できる
- [ ] 本の一覧、検索、詳細、編集、削除ができる
- [ ] 本一覧の初期表示と「条件をクリア」後がタイトル昇順で、選択欄・表示中の並び順と一致する
- [ ] 保管場所「未設定」は保管場所のない本だけ、分類タグ「未設定」はタグが0件の本だけを抽出する。両方の組み合わせ、他のタグ・保管場所との組み合わせ、キーワード・ページングも確認する
- [ ] 本一覧を下までスクロールして「詳細」を押しても本詳細はページ先頭から表示される。編集・本登録への遷移も先頭から表示される
- [ ] 本詳細の「一覧へ戻る」が情報カードの外（上側）にあり、編集・削除はカード内に残る
- [ ] 本登録・編集のラベル横に小さい丸い「？」があり（見た目約20px、タップ領域約36px）、再タップ・外側タップ・Escape・Tabで別の入力へ移動した場合に閉じられる
- [ ] スマホ幅でも説明ポップオーバーが画面外にはみ出ず、入力エラーと重複警告は通常どおり表示される
- [ ] 本一覧カードで保管場所は縦線の上に表示され、縦線は書名と著者のみに沿って表示される。出版日は表示され、ISBN・バーコードは「詳細情報」を展開したときだけ表示され、更新日時は小さく表示される（スマホ・PC両方、長い書名・保管場所名も確認）
- [ ] カードの「ISBN・バーコードなどの詳細情報」を開閉しても、「詳細・編集・削除」のボタン位置が動かない（PC・スマホ両方）
- [ ] PCの表形式にも出版日が表示され、未設定でもレイアウトが崩れない
- [ ] 本登録・編集の本のバーコード / ISBN欄へISBN-10を入力すると、ISBNだけに保存される
- [ ] 本のバーコード / ISBN欄へISBN-13を入力すると、ISBNと本のバーコードに保存される
- [ ] 一般JANなどISBNではないバーコードを入力すると、本のバーコードだけに保存される
- [ ] 登録済みのISBNまたは本のバーコードを入力すると、入力欄直下に赤字警告と既存本の詳細リンクが表示される
- [ ] 編集中の本自身のISBNまたは本のバーコードでは重複警告が表示されず、別の本の一致だけが表示される
- [ ] ISBNまたは本のバーコードが重複していても保存でき、管理用バーコードの重複だけは保存時に拒否される
- [ ] ISBNバーコードから書誌情報を取得できる場合、登録フォームへ反映できる
- [ ] NDL SearchまたはOpen Libraryの書誌情報が見つからない場合、手入力登録へ進める案内が表示される
- [ ] 外部書誌APIが失敗した場合も、手入力登録ができる
- [ ] JSON ExportしたデータをImportプレビューし、競合ごとに無視／上書きを選べる
- [ ] 不正なJSON、壊れた参照、重複データをImportできない
- [ ] 本登録画面のカメラ欄に常時表示の接続条件説明はなく、起動ボタン、モーダル内の案内、読み取り結果、エラー案内を確認できる
- [ ] 2段の書籍バーコードをカメラに映し、「1本ずつ」の細い枠に上段/下段の一方だけを合わせるとそのコードが入力され、枠外のコードは読み取られない。「QR・広い範囲」へ切り替えた場合はQRコードも読み取れる（iOS Safari・Android Chromeで確認）
- [ ] ガイド枠の外に下段の `192` から始まる書籍JANを残したまま、枠内に上段ISBNだけを置いても下段を誤検出しない。動画とガイドの見た目の位置が一致している（縦持ち・横持ちも確認）
- [ ] スマホではモーダルが上寄せで開き、プレビューが説明・入力先切替より上にあり、縦の短い画面でもキャンセル・入力先選択・スクロールが可能
- [ ] Webカメラ読み取りは、HTTPSまたはlocalhostの安全なコンテキストでのみ確認する

外部書誌APIの失敗を確認する場合は、テスト環境で外向き通信を一時的に遮断するなどして `/api/books/lookup` を失敗させます。エラー表示後も本登録画面を開き、タイトルなどを手入力して登録できることを確認します。

## SQLiteデータとバックアップ

- [ ] Docker Compose停止後に `data/book-manager.sqlite` が作成されている
- [ ] WALモード利用時は `book-manager.sqlite-wal` と `book-manager.sqlite-shm` の有無を確認する
- [ ] アプリケーション停止後、SQLiteファイル一式をバックアップ先へコピーできる
- [ ] バックアップから `data/` へ戻し、再起動後に蔵書データが復元される

通常のファイルコピーはアプリケーション停止中に行います。稼働中に取得する場合はSQLiteのバックアップ機能を使い、`book-manager.sqlite` だけを単独でコピーしないでください。
